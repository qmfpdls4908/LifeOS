# TroubleShot: AIService.js 반복 문법 오류

## 사건 요약
AIService.js에서 `generateWeeklyRoutine` 메서드를 수정하는 과정에서 **SyntaxError가 4회 연속 발생**하였다.
모두 코드 편집 후 검증 없이 배포하여 브라우저에서 사용자가 직접 에러를 발견하게 만든 실수다.

---

## 케이스 1: 이스케이프된 백틱 (Escaped Backticks)

**증상**
```
AIService.js:138 Uncaught SyntaxError: Invalid or unexpected token
```

**원인**
- `throw new Error(...)` 안에서 템플릿 리터럴을 사용하면서 `\`(백틱)` 대신 `\\`\`` 형태의 잘못된 이스케이프가 삽입됨.
- 코드 생성 도구가 백틱을 자동으로 이스케이프 처리하면서 문법이 깨짐.

**해결**
- 템플릿 리터럴 내부에 백틱이 포함되어야 하는 경우, 템플릿 리터럴 대신 **일반 문자열 결합(`+`)**을 사용한다.

**방지책**
> ⚠️ 템플릿 리터럴(백틱 문자열) 안에 백틱 문자를 포함하지 말 것. 불가피하면 일반 문자열(`'...' + '...'`)로 대체할 것.

---

## 케이스 2: 프롬프트 내 마크다운 백틱

**증상**
```
AIService.js:116 Uncaught SyntaxError: Unexpected identifier 'json'
```

**원인**
- AI에게 "마크다운(```json)을 사용하지 마세요"라고 프롬프트 안에 쓰면서, JS의 템플릿 리터럴 내부에 ` ``` ` 기호를 직접 삽입함.
- 템플릿 리터럴에서 ` ``` `는 문자열을 닫아버리는 역할을 하므로, 그 뒤의 `json`이 유효하지 않은 식별자로 해석됨.

**해결**
- 프롬프트에서 "마크다운 기호"를 언급할 때 실제 백틱 기호를 쓰는 대신 "마크다운 기호를 절대 사용하지 마세요" 같은 자연어 표현을 사용.
- 또는 **템플릿 리터럴 자체를 사용하지 않고 일반 문자열 결합으로 프롬프트를 작성**.

**방지책**
> ⚠️ 프롬프트 문자열에 코드 기호(```, ${ 등)를 직접 쓰면 JS 문법과 충돌한다. 프롬프트는 가능하면 일반 문자열(`'...'` + `'...'`)로 작성할 것.

---

## 케이스 3: 편집 잔여물 — 불필요한 닫는 괄호

**증상**
```
AIService.js:177 Uncaught SyntaxError: Unexpected token '}'
```

**원인**
- `replace_file_content` 도구로 코드 블록을 교체할 때, 원본 코드의 닫는 중괄호(`}`)가 교체 범위 밖에 남아있었음.
- 교체된 새 코드에도 자체적인 닫는 중괄호가 있었으므로, `}`가 하나 더 많아져서 클래스 구조가 깨짐.

**해결**
- 175번 줄의 불필요한 `}`를 제거.

**방지책**
> ⚠️ 코드 블록을 교체할 때 **교체 범위(StartLine~EndLine)를 충분히 넓게** 잡아서 원본의 닫는 괄호까지 포함시킬 것. 교체 후 반드시 함수/클래스의 중괄호 짝이 맞는지 확인할 것.

---

## 공통 방지 원칙

| # | 원칙 | 설명 |
|---|------|------|
| 1 | **백틱 금지 원칙** | AI 프롬프트 등 복잡한 문자열은 템플릿 리터럴 대신 일반 문자열 결합(`+`)을 사용한다 |
| 2 | **교체 범위 검증** | `replace_file_content` 사용 시 교체 전후의 중괄호/괄호 짝을 반드시 확인한다 |
| 3 | **편집 후 전체 확인** | 편집 후 해당 파일의 마지막 줄까지 `view_file`로 확인하여 잔여 코드가 없는지 검증한다 |
| 4 | **특수문자 회피** | 코드 내 문자열에 JS 예약 문자(`, $, {, })를 직접 쓸 때는 항상 충돌 가능성을 먼저 체크한다 |
